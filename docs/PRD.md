# PRD — Columbia Dining 대시보드

## 문제

컬럼비아 학생이 밥 먹으러 가기 전에 알고 싶은 건 세 가지다.

1. 지금 어디가 열려 있나
2. 오늘 거기 뭐 나오나
3. 몇 시까지 하나

dining.columbia.edu에는 이 정보가 다 있지만 **흩어져 있다.** 영업시간은 `/dining-hours`에, 끼니별 시간대는 식당별 페이지 본문에, 오늘 메뉴는 또 다른 페이지에. 식당이 16곳이라 "지금 열린 데 중에 뭐가 제일 나은가"를 알려면 페이지를 여러 번 왕복해야 한다. 배고픈 상태로, 대개 휴대폰으로.

## 사용자

컬럼비아 학부/대학원생. 압도적으로 모바일, 이동 중, 세션 길이 10초 미만. 로그인할 생각 없고 앱 설치할 생각도 없다. 링크 하나 열어서 답을 보고 닫는다.

## v1 스코프

**한 페이지 대시보드.** 로그인 없음, 설치 없음, 클릭 없이 스크롤만으로 답이 나온다.

포함:

- **로케이션 16곳 전부** — 다이닝홀 11(John Jay, Ferris Booth Commons, JJ's Place, Chef Mike's Sub Shop, Chef Don's Pizza Pi, Grace Dodge, The Fac Shack, Robert F. Smith, Faculty House 2F/4F, Johnny's Food Truck) + 리테일 5(Blue Java 4곳, Lenfest Café).
- **지금 열림/닫힘** — 각 카드에 상태 pill. 열려 있으면 마감 시각, 닫혀 있으면 다음 오픈 시각.
- **오늘 끼니 시간대** — Breakfast / Lunch / Afternoon Snack / Dinner의 시작·종료.
- **오늘 메뉴** — 스테이션별 항목. 기본 접힘, 탭하면 펼침.
- **정렬** — 지금 열림 → 곧 오픈 → 닫힘. 스크롤 없이 먹을 수 있는 곳이 먼저 보인다.
- **신선도 표시** — "N분 전 업데이트". 6시간 넘으면 경고 배너.

제외 (v1 아님):

| 뺀 것 | 이유 |
|---|---|
| 로그인·즐겨찾기 | 정적 JSON + localStorage로 나중에 얹으면 되는 일. 지금은 사용자가 0명이다. |
| 푸시 알림 | 서버가 필요해진다. 아키텍처 전체가 바뀜. |
| 주간 메뉴 | 데이터는 이미 `dining.json`에 7일치가 다 있다(공짜였음). UI만 안 붙였다 — v1을 한 화면으로 유지하려고. |
| dietary 필터 | 항목별 비건/할랄/글루텐프리 태그는 이미 표시된다. 필터링 UI만 뺐다. |
| 실시간 혼잡도 | 5개 식당에 API가 존재하지만 정적 사이트에서 직접 호출하면 CORS에 막힌다. 프록시 = 서버. |
| PWA / 오프라인 | 페이지가 이미 HTML 하나 + JSON 하나. 체감 이득 적음. |
| 리뷰·평점·혼잡도 | 스크레이핑으로 얻을 수 없는 데이터. 별개 제품. |

## 성공 기준

- **10초 안에 답.** 링크를 열고 "지금 어디서 뭘 먹을지"를 정하기까지, 스크롤 외의 조작 없이.
- **데이터가 6시간 넘게 stale하지 않는다.** 넘으면 사용자에게 보이게 경고한다.
- **틀린 정보를 조용히 보여주지 않는다.** 스크레이퍼가 깨졌을 때의 올바른 동작은 "옛날 데이터 + 경고"이지 "그럴듯한 반쪽 데이터"가 아니다.
- **유지보수 0에 수렴.** 세팅 후 사람 손이 필요한 경우는 컬럼비아가 사이트 마크업을 바꿨을 때뿐 (경험상 학기당 1회 이하).
- 운영비 $0.

## 비기능 요구

- 모바일 우선. 데스크톱은 같은 레이아웃이 넓어지는 정도.
- 첫 렌더 1초 이내 (정적 파일 2개 + CDN).
- 다크모드는 시스템 설정을 따른다.
- 접근성 기본: 상태를 색으로만 구분하지 않는다(pill에 텍스트 병기), 메뉴 접기는 네이티브 `<details>`로 키보드·스크린리더 대응.

## 리스크

| 리스크 | 대응 |
|---|---|
| Cloudflare가 GitHub Actions IP를 차단 | 스크레이프 실패 → 커밋 없음 → stale 배너. 감지되면 크롤 빈도를 낮추거나 실행 환경 변경. |
| 컬럼비아가 HTML 구조 변경 | `pytest`가 fixtures로 감지. 파서 수정이 유일한 정기 유지보수. |
| 컬럼비아가 스크레이핑에 이의 제기 | 학생 개인 프로젝트, 공개 페이지, 30분 간격, robots.txt 준수. 요청 오면 중단. |
| 아무도 안 씀 | v1이 작아서 손실도 작다. 그게 스코프를 이렇게 잡은 이유. |
